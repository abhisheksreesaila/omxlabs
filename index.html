1 · GPU native

Your data stays on the GPU.

In most data apps, the numbers are computed in one place and drawn in another: copied off the GPU, sent through a server, parsed by a browser, then redrawn. omxplorer is one Mojo program. Your rows stay in GPU memory, the kernels run right there, and only the answer, a few numbers, travels to the screen in the same process.

0.6ms

a chart over 1 million rows

30ms

Data, kernels and screen in one Mojo program. No server, no JSON, no browser in between (on Linux, checked).

One tap, start to finish
1 · you

Tap “Sum” in the chart's title and pick “Median”.

2 · the app

The tap is a message. update() changes the chart's state; view() describes the new screen.

3 · the engine

The group-by and median run as GPU kernels over all 1M rows, in the same process.

4 · the screen

Only what changed is redrawn, and the bars spring to their new heights.

2 · Agent native

Agents don't click. They call.

Today an agent uses an app like a tourist with a menu they can't read: it looks at a screenshot and points. In omxplorer, every button also describes itself: its name, what it needs, and whether it's allowed right now. The agent reads that list and calls the button directly.

Connect your agent in three steps

1 · Get the agent link

In a copy of the omxcode repo, run this. It prints one claude mcp add omxplorer … line; run that once.

scripts/agent.sh omxplorer

2 · Your agent sees the tools

omxplorer speaks MCP, the standard Claude Code and other agents already use. There's nothing to set up per button: every control is a tool from the first line of code.

3 · Talk instead of hunting

“Revenue by product, largest first, top 5.” Edit by talking, not by learning a thousand buttons. Or hand the agent a script and let it run.

A real session: Claude Code driving omxplorer, no screenshots

3 · Multimodal

Every kind of data, in one afternoon.

Today the sheet lives in Excel, the charts in Spotfire, the footage in a video editor and the model in a notebook, with exports in between. In omxplorer they're cards on one sheet, on one GPU, and they can be joined.

The video work below is built and checked, on a branch that hasn't been released yet (goal 39).

The drone, in one afternoon
  1. Open the telemetry.The flight's log opens as a table card on the sheet.
  2. Open the video.The chart's cursor and the map's dot follow the footage, frame by frame.
  3. Analyze.Every frame is read on the GPU, with classic vision today and a model next. Each asset and defect becomes a row.
  4. Compare flights.What got worse since last time is one query, joining video rows with the last flight.
  5. Plan the next one.The answer becomes the next flight plan. Every step is an agent tool.

Both clips: real recordings of omxplorer driven by its agent tools (goal 39). The footage is generated, so we know the truth of every frame; real-world footage hasn't been tried yet.
