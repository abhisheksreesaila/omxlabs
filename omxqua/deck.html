Your CSS uses tokens. Never a raw value.

.oq-root {
  --oq-radius-card: 14px;  /* families set 12 / 16 / 22 */
  --oq-target: 36px;       /* families set 34 / 40 / 48 */
  --oq-spring-fast: linear(0, 0.02, 0.071, 0.142, … 1.023, … 1); /* k380 c30 */
}
.oq-family-dev.oq-night { --oq-surface-0:#0b0b0d; --oq-surface-1:#151518; --oq-ink:#ededef; … }
.oq-night.oq-app-violet { --oq-accent: #b39dff; --oq-on-accent: #0b0b0d; }

/* yours: a new part, built only from tokens */
.receipt { background: var(--oq-surface-1); border-radius: var(--oq-radius-card);
           box-shadow: var(--oq-shadow-1); min-height: var(--oq-target);
           transition: transform var(--oq-spring-fast-dur) var(--oq-spring-fast); }

The motion budget

The more often it happens, the less it moves.

280ms

Settle. Panels and sheets: fade and a 12 px rise. No bounce.

220ms

Gentle. Menus, popovers, toasts: in softly, out in 150 ms.

0ms

None. Anything repeated many times a minute, live data, the keyboard.

Springs are only for small things under your finger. The press squashes 0.90 small, 0.96 medium, 0.985 large, so it feels the same at every size.

The honest edges

What it isn't, yet.

🪟 One bit of glass.

The nav pill and tab bar are frosted, so the page shows through. Every card, menu and dialog stays solid.

🌐 Web only, for now.

It's CSS and JS. omxplorer and the other omxcode apps still draw with their own Mojo themes.

🧩 Some glue is still inline.

Dialog and sheet open/close and menu placement live in the showcase, not in omxqua.js.

🔍 One contrast gap.

The field outline is 1.3:1 against its card, below the 3:1 a control's edge should have.
